# 構成案 v7：図版を使う高密度15枚構成

## 編集方針

- 20枚を15枚へ圧縮する
- 1枚に「事実」「具体例」「そこから言えること」を入れる
- 左に課題・従来・負担、右に対応・現在・成果を置く
- 制度や活動を1枚ずつ紹介せず、因果関係のある内容を同じスライドへまとめる
- 写真だけのスライド、結論だけのスライド、独立した経歴紹介は作らない

## 13. LLMの移動要約を、Akinator式の質問で再識別できるか測りました

左：提案アルゴリズム N(D)

- 位置履歴を構造化し、LLMで文章要約
- 候補者200人と質問プールを用意
- 情報利得が最大の質問を選ぶ
- LLM Oracleが要約だけを見てyes/no/unknownで回答
- 正しく1人に絞るまでの質問数をN(D)と定義
- 少ない質問ほど再識別リスクが高い

右：100人を対象にした結果

- 未加工では99人を正しく特定
- 最強の数値摂動では正解6人、誤分離82人
- 成功例の平均N(D)は11.63から17.83へ増加
- 17.83は正しく特定できた6人のみの平均

## 14. AIで英語を書いても、査読者が評価したのは新規性と評価設計でした

左：実際の査読コメント

- Highly Novel Contribution
  - sequential questioningで自由記述の再識別リスクを測る、fundamentally new approach
  - significant conceptual advance
- Rigorous Technical Framework
  - mathematically sound
  - N(D)と失敗診断を分けた点がparticularly thoughtful
- Comprehensive Experimental Design
  - 複数のプライバシー保護条件を同じ監査手順で系統的に比較

右：査読者が新規性と見た部分

- 固有表現検出や静的な匿名性指標から離れた
- 攻撃者が質問を重ねる過程をモデル化
- 成功時だけN(D)を定義し、失敗を別に記録
- 誤分離、真の候補除外、情報枯渇を区別
- 数値摂動、属性除去、要約抽象度を比較
- AIが書いた英語でも、評価対象は研究設計

下部：英語を作る工程はAIで短縮できる。それでも、新しい問いと検証可能な評価設計がなければ査読は通らない。
